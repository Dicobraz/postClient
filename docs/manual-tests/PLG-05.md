# PLG-05. Канал Telegram — отдельным процессом набора postman-plugins

Статус: ⏳ (ручная проверка — владелец, тестовый аккаунт Telegram, сборка с ключом приложения)

Подготовка: канал работает процессом общего набора `postman-plugins` (ADR 0013, PLG-05) — файл набора лежит рядом с
`postman.exe`, как воркер. Dev-сборка: `cargo build -p postman-gpui -p postman-plugins` и запуск
`target/<платформа>/debug/postman.exe` (файл набора — `postman-plugins[.exe]` там же; пока упаковки набора нет —
PLG-03, release-проверка требует положить файл рядом с `postman.exe` вручную). Ключ приложения — переменные
`POSTMAN_TG_API_ID`/`POSTMAN_TG_API_HASH` при сборке **набора** (в CI — из секретов `TKNAPPID`/`TKNZORIO`): `postman.exe`
ключ больше не знает, наличие ему сообщает плагин в `Hello`. Без ключа вход отказывает «В этой сборке нет ключа
приложения Telegram». Вид бесед — CH-04: здесь проверяются вход, подключение и обмен с процессом.

1. «Настройки → Аккаунты» → «Каналы бесед»: «Telegram» выключен (признака сборки больше нет — строка есть в любой
   сборке). Включить — «Добавить учётку Telegram». Политика `AllowChannelTelegram = 0` (реестр,
   `Software\Policies\Pets\Postman`) — строки нет; `= 1` — включён, выключатель недоступен.
2. Файла набора рядом нет (переименовать `postman-plugins[.exe]`) — «Добавить учётку Telegram» → карточка входа
   закрывается ошибкой «проблема с плагином… перезапустите Postman» (журнал: `plugin not used: plugin set
   postman-plugins not found`), без перезапусков и без сетевой активности. Вернуть файл — следующий шаг входа
   проходит без перезапуска Postman.
3. Вход по номеру (сборка без ключа): кнопка «Добавить учётку Telegram» есть, после неё — «В этой сборке нет ключа
   приложения Telegram»; строка «Добавить учётку» сменяется подсказкой «нет ключа». Сборка с ключом — как было
   (CH-03): телефон → код → пароль двухэтапной проверки; вопросы и ответы идут процессом, в `postman.exe` сети нет.
4. Вход по QR: «Войти по QR-коду» → QR (тёмный на светлом в любой теме). Телефон: Telegram → «Настройки» →
   «Устройства» → «Подключить устройство» — навести камеру: вход прошёл (с паролем двухэтапной проверки — поле
   пароля). Подождать 30 с не сканируя — QR обновился (процесс запросил новый токен). «Войти по номеру телефона» —
   снова поле телефона.
5. Процесс: в диспетчере задач после входа — `postman-plugins[.exe]` (один на все учётки Telegram). Завершить его
   принудительно — строка учётки «Нет связи, повтор через N с», затем «В сети» без нового входа (хост перезапустил
   процесс, догон от курсора; правки, отправленные «в без связи», дошли). Пять завершений подряд за 10 минут —
   «проблема → причина» с кнопкой «Повторить» (после неё — подъём процесса).
6. Перезапуск Postman — учётка «В сети» без нового входа (секрет — в диспетчере учётных данных, запись
   `Postman channel telegram <id>`; файлов сессии рядом с базой профиля нет — состояние канала в базе, у процесса
   своих файлов нет).
7. Диалоги и реальное время (CH-03 пп. 6–7): с телефона написать в личную и группу — `channel: conversations
   changed` в журнале за секунды; правка, удаление, реакции — так же. История: прокрутка ленты вверх — страницы
   истории от процесса.
8. Отправка, правки, файлы (вид бесед — CH-04; здесь — по журналу и с телефона): отправить текст и картинку — на
   телефоне пришли; правка своего — изменилась; «прочитано» с телефона — счётчик ушёл.
9. Выключить «Telegram» в настройках — учётки не подключаются (процесс завершается, когда учёток и входов нет),
   данные остаются до «Выйти». «Выйти» — строки нет, в Telegram на телефоне сеанса «Postman» нет, записи секрета и
   данных `chan/telegram/…` в базе профиля нет.
10. Замер: `--bench` (демо-ящик) — `plugin_start_ms` (создание процесса → `Hello`) единицы десятков миллисекунд,
    `first_frame_ms` не хуже прежнего (процессы плагинов — после первого кадра).
