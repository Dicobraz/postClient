# PLG-08. Услуги ядра почтовому пути; Exchange (EWS) — процессом `postman-plugins`; окно «Отменить» — у ядра

Статус: ⏳ (ручная проверка — владелец; нужен стенд Exchange — учётка EWS (`docs/EXCHANGE.md`): почта, папки,
календарь, занятость, справочник; вход учётной записью Windows — машина в домене стенда; функциональная часть
Exchange — S7-06г, T1-02а/б, здесь — поведение процесса, услуг ядра и очереди отправки).

Подготовка: сборка из дерева — `cargo build -p postman-gpui -p postman-plugins` (в общем файле набора — демо-канал,
каталог LDAP, DAV и EWS; `postman-backend-ews` больше нет в `postman.exe` — проверка: `cargo tree -p postman-gpui -e normal -i postman-backend-ews`
пусто). Процессы смотреть: Windows — «Подробности» диспетчера задач (`postman-plugins.exe`), Linux —
`ps -o pid,rss,cmd -C postman-plugins`.

## Учётка EWS — почта и области одним процессом

1. Добавить учётку EWS (`https://…/EWS/Exchange.asmx` или узел с autodiscover): почта, папки, календарь, занятость
   и справочник работают как были; в журнале — запуск плагина `ews` (`plugin started`) и `sync backend: ews`.
   Почта и области EWS — один процесс `postman-plugins --plugin=ews` (второго процесса нет).
2. Первая синхронизация по скорости не хуже прежней (внутри `postman.exe`): те же 500 писем первых папок, время до
   `Status::Synced` и `first_sync_ms` замера — не хуже чем на 10 % (хранилище учётки теперь по обмену: записи идут
   подряд без ответа, ошибка — на ближайшем чтении).
3. Открытие письма, вложение, картинка, цепочка, поиск по папке и «Все папки», «Прочитано»/флаг, перенос и удаление,
   создание/переименование/перенос папки (T1-04в) — как были; при падении `postman-plugins.exe` следующая команда
   поднимает процесс заново (сессия входит сама, переподключения учётки не требуется; пять падений за 10 минут —
   «проблема» и «Повторить»).
4. Области у IMAP-учётки на Exchange (`imaps://…?ews=https://…/EWS/Exchange.asmx`): календарь, занятость и
   справочник — тем же процессом набора, что и почта Exchange (`postman-plugins.exe` один).
5. Ответ на приглашение (по встрече Exchange, без ответа и с комментарием — письмом), новая встреча, неделя,
   «Сообщить о занятости» — как были; `Command::Tasks` области EWS не получают (задач у Exchange нет).

## Вход учётной записью Windows

6. Вход с пустым паролем («Войти как пользователь Windows», T1-02а): машина в домене — вход Kerberos/SSPI, адрес
   ящика — у сервера (`ResolveNames`); вне домена или без билета — строка «войти с паролем» (род ошибки
   `WindowsSignInUnavailable` — часть договора, строка входа отгадывает по роду, не по тексту).
7. Неверный пароль или логин не того вида (адрес почты вместо `DOMAIN\user`): причина — с подсказкой про вид логина
   (род `CredentialsRejected`); поле логина на строке входа у EWS-адреса — как было.

## Окно «Отменить» и «Отправить позже» — у ядра

8. «Отменить» (задержка 5/10/30 с, CMF-03): тост с обратным отсчётом, «Отменить» возвращает письмо в окно
   составления — путь-процесс письмо в окне не видит (оно в очереди ядра в базе профиля); по истечении окна письмо
   уходит в Exchange, копия в «Отправленных» — от сервера.
9. Убить `postman-plugins.exe` во время окна «Отменить»: письмо не теряется — процесс поднимается и письмо уходит
   (тест `backend::mail::tests::a_letter_from_a_crashed_run_leaves_at_the_next_sign_in`).
10. Закрыть Postman в окне «Отменить»: письмо уходит при выходе (выход дожидается очереди ядра — не дольше
    `LEAVE_LIMIT`); закрыть программу совсем (убить процесс) — при следующем запуске письмо из базы уходит сразу.
11. «Отправить позже» у Exchange — нет (`max_delay: 0`, интерфейс пункт прячет); команда `Scheduled` отвечает
    содержимым очереди ядра (после отмены — пусто).

## Выход и сборка

12. Выход программы с несколькими учётками (IMAP с окном, EWS с окном, каналы с очередью): все письма в окнах
    уходят, процесс дожидается очередей ядра и каналов (`finish_sends`) — письма не теряются.
13. `postman-ews` вне дерева `postman-gpui`: `cargo tree -p postman-gpui -e normal | grep postman-backend-ews` —
    пусто; тест слоёв (`layers.rs`, `LINKED_FOR_NOW` без ews) зелёный; строка `ews` в корне совпадает с мнением
    набора (тест `rows_match_the_plugin_sets`).
14. Замер №19 (`docs/SIZE.md`): release-сборка `postman` (без EWS — ожидаемо меньше), `postman-plugins` (демо +
    LDAP + DAV + EWS — больше на стек EWS/SSPI), `postman-worker` — без изменений.
