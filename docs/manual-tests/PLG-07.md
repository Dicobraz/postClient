# PLG-07. Календарь, задачи и контакты — области процессом `postman-plugins`; публичные загрузки процессом

Статус: ⏳ (ручная проверка — владелец; нужны стенд Stalwart — учётка «стандарты» IMAP + CalDAV/CardDAV
(`docs/STALWART.md`) и стенд сети для картинок/подписок; функциональная часть — `S7-05б`, `S8-42`, `S8-44`, здесь
поведение процесса и развода команд ядром).

Подготовка: сборка из дерева — `cargo build -p postman-gpui -p postman-plugins` (в общем файле набора — демо-канал,
каталог LDAP и DAV; `postman-backend-dav` больше нет в `postman.exe` — проверка: `cargo tree -p postman-gpui -e normal -i postman-backend-dav`
пусто). Процессы смотреть: Windows — «Подробности» диспетчера задач (`postman-plugins.exe`), Linux —
`ps -o pid,rss,cmd -C postman-plugins`.

## Учётка «стандарты» — области процессом

1. Добавить учётку `imaps://…?smtp=…&dav=https://…` («стандарты»): календарь, задачи и контакты работают как были
   (`Features` объединяет ядро — «Нет у сервера — нет на экране»). В журнале — запуск плагина `dav` (`plugin started`),
   строки `sync backend: imap` и подключение области.
2. Событие недели, встреча с рассылкой сервером (SCHEDULE-AGENT=SERVER), ответ на приглашение своей копией
   (REPLY шлёт сервер), «без ответа» и «с комментарием» — письмом организатору (iMIP делает почтовый путь IMAP в
   `postman.exe`, копию — область-процесс: раздельные отказы видны по отдельности — календарь тостом, письмо —
   ошибкой отправки).
3. Задачи двумя клиентами (создание, правка, удаление, подзадачи, «Время в календаре»): список из кэша мгновенно,
   дельта — сервером; правки без связи остаются помеченными и уходят при возврате (`Flush`) — теперь через процесс
   по обмену (ядро хранит кэш и очередь, плагин — сервер).
4. Контакты CardDAV: список, правка построчно, группы; справочник организации скрыт (`Features` — у CardDAV его
   нет), список рассылки — «не поддерживается» (T3-09).
5. Опрос без push: правка у второго клиента доезжает до первого не дольше 2 минут (ctag/sync-token — таймер ядра
   раз в 2 минуты, как `POLL` у IMAP раньше); в журнале ошибки опроса — `DEBUG` (без связи календарь не сыплет
   тостами).
6. Убить `postman-plugins.exe` из диспетчера во время работы календаря: следующая команда (неделя, встреча)
   отвечает отказом и поднимает процесс заново; сессия учётки входит сама — переподключения учётки не требуется.
   Пять падений за 10 минут — «проблема» и «Повторить» (как у каналов).
7. Простой: учётку отключить (или выйти) — без открытых сессий областей процесс завершается после 5 минут без
   запросов (`plugin idle for 5 min, stopped until the next request` в журнале); подписка/картинка/вход учётки
   поднимает его снова.
8. Учётка IMAP на Exchange (`?ews=…`): календарь и справочник EWS работают по-прежнему внутри `postman.exe` —
   процесс `postman-plugins` для них не поднимается (до PLG-08).

## Публичные загрузки — процессом

9. Картинка письма по `https://`-ссылке (S8-42): загружается как была; `webcal://` — тоже (`https` внутри).
   Ссылки `http://`, `https://localhost/…`, с именем пользователя в адресе — не загружаются (проверка адреса
   делает ядро до запуска процесса).
10. Подписка на календарь по ссылке (S8-44): добавление проверяет адрес без процесса; обновление подписки идёт
    процессом DAV, `ETag` экономит трафик (не менялся — «не менялся», в журнале `DEBUG`); процесс, поднятый
    подпиской, завершается после 5 минут простоя.
11. «Открыть занятость» по ссылке (S8-42): занятость коллеги строится как была — тем же процессом.

## Сборка и размеры

12. `postman-dav` вне дерева `postman-gpui`: `cargo tree -p postman-gpui -e normal | grep postman-dav` — пусто;
    тест слоёв (`layers.rs`, `LINKED_FOR_NOW` без dav) зелёный.
13. Замер №18 (`docs/SIZE.md`): release-сборка `postman` (без dav — ожидаемо меньше), `postman-plugins` (демо +
    LDAP + DAV — больше на стек DAV), `postman-worker` — без изменений.
