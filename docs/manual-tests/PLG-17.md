# Ручная проверка PLG-17: пакеты без файлов каналов, компонентные ассеты

Проверяет владелец по артефактам job `release` этого PR (первый прогон с PLG-17): в базовых пакетах нет файлов
каналов, компонентные zips опубликованы и подписаны, докачка приложения работает на трёх ОС
(решение 2026-11-19 `docs/decisions/2026-11-19-components.md`).

1. **Windows MSI**: установить с `CHANNELS=none` и с умолчанием (PLG-13, `msi-check` уже проверяет оба) — файлы
   каналов только там, где просили. Windows zip: файлов каналов нет; в выпуске есть
   `postman-plugins-telegram-windows-x64.zip` (+ `.minisig`).
2. **Windows докачка**: включить Telegram в настройках — «Скачать» качает ассет выпуска, канал поднимается
   (сценарий `docs/manual-tests/PLG-15.md`), файл в `%LOCALAPPDATA%\Postman\Components`.
3. **Linux**: deb/rpm/AppImage без `postman-plugins-telegram|matrix`; в выпуске есть `…-linux-x64.zip`.
   Ubuntu 24.04: `apparmor_parser` ставит профиль `postman-components` (паттерн каталога компонентов);
   `--install-component`/«Установить из файла» тем же файлом — канал работает (PLG-16).
4. **macOS**: в `Postman.app/Contents/MacOS` — только постман/воркер/просмотрщик/набор; в выпуске —
   `…-macos-arm64.zip`; докачка или файл — как в п. 3.
5. **Обновление**: поставить пакет следующей версии без каналов — компоненты в `Components` переживают
   обновление, после самообновления приложение помечает их «скачайте заново» (PLG-15).
6. **winget**: установка по умолчанию (тихая, без `CHANNELS`) ставит всё вместе с каналами (PLG-13) —
   сознательное исключение из «пакетов без каналов»: у MSI файлы внутри и умолчание «всё».
