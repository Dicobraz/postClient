# PLG-04. Канал Matrix — процессом набора `postman-plugins-matrix`

Статус: ⏳ (ручная проверка — владелец; функциональная часть — вход, комнаты, шифрование, проверка устройства —
в `CH-05.md`, здесь поведение процесса. Тестовая учётка на matrix.org или своём сервере Matrix.)

Подготовка: пакеты PLG-03 (MSI/zip, `.app`, deb/rpm/AppImage) кладут `postman-plugins-matrix` рядом с `postman`;
из дерева — `cargo build -p postman-gpui -p postman-plugins-matrix`. Процессы смотреть: Windows — «Подробности»
диспетчера задач, macOS — «Мониторинг системы», Linux — `ps -o pid,rss,cmd -C postman-plugins-matrix`.

1. До включения канала «Matrix» («Настройки → Аккаунты» → «Каналы бесед») процесса `postman-plugins-matrix` нет.
   Включить «Matrix», «Добавить учётку Matrix» — процесс поднялся (журнал `Debug` — строка запуска плагина), вход
   прошёл как в `CH-05.md` п. 2–3.
2. Память процесса: в простое после догона комнат и в активности — записать в журнал проверки (нужно для PLG-12,
   `plugins_rss_mb`). Перезапуск Postman — процесс поднялся сам, учётка «В сети» без нового входа.
3. Убить процесс из диспетчера: у строки учётки «Нет связи» / «проблема → причина», через секунды процесс
   поднялся сам, пропущенное догнано; письмо, отправленное в момент убийства, не потерялось и не задублировалось.
4. Убивать процесс быстро пять раз за десять минут — автоперезапуск останавливается (ADR 0013: до просьбы
   пользователя), в журнале причина; перезапуск Postman возвращает автоподъём.
5. Файл набора: при остановленном Postman переименовать `postman-plugins-matrix` — включение «Matrix» даёт
   «проблема → причина» у учётки, падений нет; вернуть имя — работает без переустановки.
6. Хранилища SDK: рядом с базой профиля нет `*.sqlite3` и папок matrix-sdk (данные канала — в базе профиля через
   услугу хранилища); секрет — в диспетчере учётных данных, запись `Postman channel matrix @имя:сервер`.
7. Вход через браузер (`CH-05.md` п. 3): слушатель `127.0.0.1` теперь у ядра (песочница плагина входящих не
   принимает) — поведение то же, «Вход выполнен — вернитесь в Postman».
8. Windows/macOS: сетевая часть сквозного теста процесса в CI пропускается (изоляция loopback у AppContainer,
   Seatbelt) — эта проверка и есть полный прогон канала на этих системах.
