# PLG-10. JMAP (The Post) — процессом `postman-plugins`; в `postman.exe` сетевого стека протоколов больше нет

Статус: ⏳ (ручная проверка — владелец; нужен стенд The Post — учётка JMAP (`POSTMAN_STAND_*`,
`backend-jmap/tests/`): почта, календарь, контакты, задачи, правила, автоответ; функциональная часть JMAP —
S7-02б, здесь — поведение процесса, услуг ядра и очереди отправки).

Подготовка: сборка из дерева — `cargo build -p postman-gpui -p postman-plugins` (в общем файле набора — демо-канал,
каталог LDAP, DAV, EWS, IMAP и JMAP; `postman-backend-jmap` больше нет в `postman.exe` — проверка: `cargo tree -p postman-gpui -e normal -i postman-backend-jmap`
пусто; сетевой стек протоколов тоже: `cargo tree -p postman-gpui -e normal | grep -E "reqwest|rustls v"` — пусто (разбор сертификатов S/MIME — rustls-pki-types/webpki, он был всегда).
Процессы смотреть: Windows — «Подробности» диспетчера задач (`postman-plugins.exe`), Linux —
`ps -o pid,rss,cmd -C postman-plugins`.

## Основная учётка — всё одним процессом

1. Добавить учётку JMAP (узел без схемы — определится по `/.well-known/jmap`, или `https://…`): почта, папки,
   календарь, контакты, задачи, правила, автоответ, категории — как были; в журнале — запуск плагина `jmap`
   (`plugin started`) и `sync backend: jmap`. Всё — один процесс `postman-plugins --plugin=jmap` (процесс DAV
   стартует отдельно, только если у учётки есть `?dav=…`).
2. Первая синхронизация по скорости не хуже прежней (внутри `postman.exe`): те же 500 писем первых папок, время
   до `Status::Synced` — не хуже чем на 10 % (хранилище учётки теперь по обмену: записи идут подряд без ответа,
   ошибка — на ближайшем чтении).
3. Push (EventSource): новое письмо, изменение папки, календаря или задач приходит в открытый Postman без
   действий; поиск по письмам («Все папки», панель) находит и новое письмо — индексирует ядро услугой
   (`FromPlugin::Index`).
4. Задачи: создание, срок, связь с письмом (ссылки «письмо ↔ задача») — как были; правки задач при обрыве связи
   остаются в кэше и уходят при восстановлении (`Reconcile`/`Flush` — хранилище задач по обмену).
5. Правила, автоответ, квота, категории (полосы и метки), общие и делегированные ящики (S4-06), «Отправить
   позже» сервером (планирование в календаре) — как были.

## Отправка, «Отменить», выгрузка

6. Отправка письма (в том числе «Конфиденциально» — S/MIME услугой ядра, ключи у ядра) и отмена в окне — как у
   IMAP/EWS: письмо в окне видит ядро (`MailQueue`), путь получает его в момент отправки; «Отправить позже» —
   сервером JMAP, как было.
7. Убить `postman-plugins.exe` во время окна «Отменить»: письмо не теряется — процесс поднимается, письмо уходит
   (очередь ядра).
8. Выгрузка письма из другой учётки (S8-13, `Import` — `APPEND`-аналог JMAP) и перенос между учётками сервером
   (`Email/copy`, если сервер объявил) — как были.

## Вход, политика TLS, сборка

9. Вход по токену (Bearer): учётка добавляется токеном — путь в процессе получает его по обмену
   ([`MailLogin::bearer`]); неверный токен — отказ входа с причиной, как был.
10. «Настройки → Безопасность → Только TLS 1.3»: новая учётка входит по политике (процесс читает настройки ядра
    на входе); смена политики при живой сессии доезжает после её следующего входа (записано в карточке —
    «Не сделано»).
11. `postman-backend-jmap` и `postman-jmap` вне дерева `postman-gpui`: `cargo tree -p postman-gpui -e normal | grep -E "backend-jmap|postman-jmap"`
    — пусто; тест слоёв (`layers.rs`, `LINKED_FOR_NOW` пуст) зелёный; строка `jmap` в корне совпадает с мнением
    набора (тесты `rows_match_the_plugin_sets`, `set_entry_matches_the_row`).
12. Замер №21 (`docs/SIZE.md`, догоняющим коммитом): release-сборка `postman` (без JMAP и сетевого стека —
    ожидаемо заметно меньше), `postman-plugins` (демо + LDAP + DAV + EWS + IMAP + JMAP — больше).
