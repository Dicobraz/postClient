# PLG-09. IMAP + SMTP — процессом `postman-plugins`; IDLE и отправка SMTP — в процессе, окно «Отменить» — у ядра

Статус: ⏳ (ручная проверка — владелец; нужен стенд «стандарты» — учётка IMAP+SMTP (`POSTMAN_STAND_*`,
`backend-imap/tests/stand_imap.rs`): почта, папки с ролями, IDLE, отправка, перенос; функциональная часть IMAP —
S7-02б/04в, здесь — поведение процесса, услуг ядра и очереди отправки).

Подготовка: сборка из дерева — `cargo build -p postman-gpui -p postman-plugins` (в общем файле набора — демо-канал,
каталог LDAP, DAV, EWS и IMAP; `postman-backend-imap` больше нет в `postman.exe` — проверка: `cargo tree -p postman-gpui -e normal -i postman-backend-imap`
пусто). Процессы смотреть: Windows — «Подробности» диспетчера задач (`postman-plugins.exe`), Linux —
`ps -o pid,rss,cmd -C postman-plugins`.

## Учётка IMAP — почта одним процессом

1. Добавить учётку IMAP (`imaps://…`, при желании `?smtp=…` и `?dav=…`): почта и папки работают как были; в журнале —
   запуск плагина `imap` (`plugin started`) и `sync backend: imap`. Почта — процесс `postman-plugins
   --plugin=imap`; области учётки (`dav=`) — отдельный процесс того же набора (`--plugin=dav`), календарь и
   контакты — как были (PLG-07).
2. Первая синхронизация по скорости не хуже прежней (внутри `postman.exe`): те же 500 писем первых папок, время до
   `Status::Synced` — не хуже чем на 10 % (хранилище учётки теперь по обмену: записи идут подряд без ответа, ошибка —
   на ближайшем чтении).
3. IDLE на «Входящих»: новое письмо на сервере приходит в открытый Postman без действий (`EmailsChanged`); обрыв
   связи — восстановление при следующей команде/опросе, не мёртвое до перезапуска.
4. Открытие письма, вложение, картинка, цепочка, поиск (`SEARCH` на сервере), «Прочитано»/флаг, перенос и удаление,
   создание/переименование/перенос папки (RENAME — ключи писем в кэше перелицовываются, `LetterId` те же) — как
   были; при падении `postman-plugins.exe` следующая команда поднимает процесс заново (сессия входит сама).
5. «Отправить позже» у IMAP — нет (`max_delay: 0`, интерфейс пункт прячет); `Command::Scheduled` отвечает
   содержимым очереди ядра.

## Окно «Отменить» и очередь — у ядра

6. «Отменить» (задержка 5/10/30 с, CMF-03): тост с обратным отсчётом, «Отменить» возвращает письмо в окно
   составления — путь-процесс письмо в окне не видит (оно в очереди ядра в базе профиля); по истечении окна письмо
   уходит через SMTP, копия — `APPEND` в «Отправленные».
7. Убить `postman-plugins.exe` во время окна «Отменить»: письмо не теряется — процесс поднимается, письмо уходит
   (очередь ядра; тест `backend::mail::tests::a_letter_from_a_crashed_run_leaves_at_the_next_sign_in`).
8. Закрыть Postman в окне «Отменить»: письмо уходит при выходе (выход дожидается очереди ядра — не дольше
   `LEAVE_LIMIT`); убить программу совсем — при следующем запуске письмо из базы уходит сразу.
9. S/MIME «Конфиденциально» (ключи у ядра): отправка запечатанного письма через SMTP — получатель расшифровывает;
   путь процесса ключей не получает (услуга `seal_outgoing` по обмену).

## Перенос и выход

10. Перенос писем из другой учётки (S8-13): выгрузка `APPEND` (флаги, `INTERNALDATE`, квота — если `QUOTA`),
    повтор по `Message-ID`, удаление у источника — как были; квота — «Настройки», если сервер объявил.
11. Шаг поручения (S6-09): письма iTIP уходят сразу (окно «Отменить» у шагов больше не держится путём — очередь
    ядра держит окно только у `Send`); копия задачи — на CalDAV как была (PLG-07).
12. Выход программы с несколькими учётками (IMAP с окном, EWS с окном, каналы с очередью): все письма в окнах
    уходят (`finish_sends` дожидается очереди ядра и каналов) — письма не теряются.
13. `postman-backend-imap` вне дерева `postman-gpui`: `cargo tree -p postman-gpui -e normal | grep postman-backend-imap`
    — пусто; тест слоёв (`layers.rs`, `LINKED_FOR_NOW` без imap) зелёный; строка `imap` в корне совпадает с
    мнением набора (тесты `rows_match_the_plugin_sets`, `set_entry_matches_the_row`).
14. Замер №20 (`docs/SIZE.md`, догоняющим коммитом): release-сборка `postman` (без IMAP — ожидаемо меньше),
    `postman-plugins` (демо + LDAP + DAV + EWS + IMAP — больше на стек IMAP/SMTP).
