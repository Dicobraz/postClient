# AUD-08. Политика «только TLS 1.3» — почта Exchange (EWS) и IMAP/SMTP в процессах плагинов

Статус: ⏳ (ручная проверка — владелец; нужен сервер, принимающий и TLS 1.2, и TLS 1.3: Exchange с EWS,
у которого включён IMAP/SMTP, либо IMAP-хостинг; политика `MinTls` = `1.3` — POL-01).

Подготовка: сборка из дерева — `cargo build -p postman-gpui -p postman-plugins`. Политика включается
`Software\Policies\Pets\Postman` → `MinTls` = «1.3» (или «Настройки → Безопасность → Только TLS 1.3»);
включённое видно в настройках. Журнал — «Настройки → Общие → Уровень журнала» = `debug`.

## Почта Exchange (EWS, процесс `--plugin=ews`)

1. Учётка Exchange по EWS (почта + календарь) при политике «только 1.3»: вход, письма, отправка, календарь —
   работают; в журнале процесса нет ошибок вида `tls: ... protocol version` (сервер согласил 1.3).
2. Снять политику, перезапустить: то же самое — работает (минимум 1.2).
3. Если сервер принудительно держит только TLS 1.2, а политика включена: вход не удаётся, в журнале —
   сетевая ошибка рукопожатия, интерфейс показывает ошибку учётки (политика не понижается молча).

## IMAP/SMTP (процесс `--plugin=imap`)

4. Учётка `imaps://…` (приём IMAP 993, отправка SMTP 465) при политике «только 1.3»: письма приходят
   (IDLE — тоже), отправка уходит, копия кладётся в «Отправленные».
5. Учётка `imap://…`/587 (STARTTLS) при политике: после STARTTLS рукопожатие идёт по 1.3 — письма и отправка
   работают.
6. Смена политики на включённой учётке: применяется со следующего входа учётки (ограничение PLG-10); до
   перезапуска процесса живые соединения — по старой политике.

## Где смотреть (без стенда)

- Юнит-тесты пламбинга: `cargo nextest run -p postman-imap -p postman-ews` — политика переключает версии
  коннектора IMAP (1.3 ↔ 1.2+1.3) и минимальную версию конструктора SChannel у EWS (1.3 ↔ 1.2).
