## Задача
- Возврат приоритета процесса стоял только на `ChannelEvent::Cursor` (каналы): процессы почтовых путей
  (IMAP, JMAP, EWS), областей (DAV) и каталога (LDAP) оставались с пониженным приоритетом процессора и
  ввода-вывода на всё время жизни.
- Возврат должен срабатывать и по первому событию синхронизации почтового пути — семантика «первая
  синхронизация» консервативная, как у каналов (первый курсор/первый пакет событий).

## Сделано
- Хелпер `Conn::restore_priority` (один `swap` пониженного флага + возврат с журналом) вместо повторов в
  трёх ветках `Conn::serve`.
- Почтовый путь: первый пакет событий синка (`MailboxesChanged`, `EmailsChanged`, `BodiesStored`,
  `Status::Synced` — `mail_sync_packet`); статусы входа («подключение», «вошли», «загрузка») пакетом не
  считаются — по ним возвращать рано.
- Области (DAV) и LDAP: у областей статусов входа нет — любое `AreaEvent` (первое событие команды) —
  возврат; каталог не синхронизируется, остаётся как был.
- Тест `first_mail_sync_packet_restores_the_process_priority` (по образцу
  `two_starts_at_most_preferred_first`): запуск понизил приоритет (`background(true)`), первый пакет событий
  синка вернул (`background(false)`); запускатель теста теперь ведёт журнал вызовов `background`.

## Не сделано
- Отдельный тест для областей: ветка та же (один вызов `restore_priority`), событие области в тестах
  подменного пути не воспроизводится без полной сессии областей — покрыто тестом почтового пути.
