## Задача
- Крейт `backend-matrix` по договору каналов (кандидат `matrix-sdk`, Apache-2.0): вход (пароль, SSO), комнаты,
  история, sync, отправка, ответы, правки, реакции, «прочитано».
- Сквозное шифрование в клиенте: проверка устройств, резервная копия ключей.
- Мосты Matrix к другим сетям — не в клиенте; если понадобятся — на сервере, отдельным решением владельца.

## Готово
Вход, комнаты, шифрованная переписка на тестовом сервере (ручная проверка); договор — тестами.

## Сделано
- Крейт `crates/backend-matrix` (L2b, ADR 0012 п. 12): `matrix-sdk` 0.19.1 (Apache-2.0; сквозное шифрование
  `vodozemac`, сеть — тот же reqwest/rustls). Лицензии зависимостей: Apache-2.0/MIT/BSD и MPL-2.0 (`eyeball`, `imbl`,
  `readlock`, `as_variant` — пофайловое copyleft, как `option-ext` в main). Повторы SDK выключены — паузу держит ядро.
- Хранилища SDK — свои, в базе профиля через `PluginStore` (`store`): `StateStore` и `CryptoStore` поверх `MemoryStore`
  SDK с записью в `local["chan/matrix/<учётка>/mx/…"]`, значения зашифрованы ключом из секрета сессии (`StoreCipher`);
  запись — очередью задачи потока учётки. Ни SQLite, ни файлов. Другое устройство или ключ — данные с чистого листа.
- Вход (`signin`): сервер (имя с well-known, адрес или `@имя:сервер`) → имя и пароль (`m.login.password`) или
  «через браузер» (SSO, возврат на `127.0.0.1:<порт>`, `m.login.token`). Вход — прямым `/login`, ключи устройства
  заводит подключение уже со своим хранилищем. Секрет (сервер, устройство, токен, ключ хранилища) — в хранилище ОС.
- Сессия (`session`): sync с курсором `next_batch` (фильтр: 50 событий, участники лениво), долгий опрос задачей,
  обрыв — `Offline`, отозванный токен — `SignedOut`. Комнаты: личные (`m.direct`), группы, роли по уровню прав,
  «только чтение», счётчики сервера, закрепление (`m.favourite`), шифрование; пространства — папками (с вложенностью).
  События: сообщения (HTML — `Body::Html`, запасные цитаты ответа отрезаются), правки (`m.replace`, своя и с сервера в
  `unsigned`), удаление (redaction), реакции (свод `/relations`), «прочитано», «печатает», участники, служебные
  строки, ветки (`thread`), упоминания (`m.mentions`), `limited` → `Gap`. Не расшифровалось — `Undecryptable` и сырое
  событие в своих данных; ключ пришёл — то же сообщение заново (тот же id).
- Действия: отправка (`txn_id = pm<client_id>`, повтор — без дубля; ответ; цитата фрагмента — блоком; файлы шифром
  `EncryptedFile`, подпись — Matrix 1.10), правка, удаление у всех, реакция и снятие, «прочитано», «печатает»,
  закрепление, новая беседа или группа, участники, ссылка → адрес; история (`/context` + `/messages`), поиск на
  сервере (`/search`), загрузка файлов (и шифрованных). `link`/`parse_link`/`person_url` — `matrix.to`, `matrix:u/…`.
- Потоки после входа (`verify`): проверка устройства (SAS, семь символов; входящий запрос с другого устройства —
  принимается) и восстановление ключей (ключ или фраза → 4S, ключи комнат с заглушками — из копии, повтор
  расшифровки). В ядре — `Request::Flow`/`Request::Answer` → `Update::Flow`.
- «Шифрованные беседы» (ADR 0012, решение п. 1): `core::channel::e2e` — «хранить и искать» / «хранить, не искать» /
  «только в памяти»; смена — документы уходят из индекса, при «только в памяти» строки переписываются без текста
  (текст — в памяти процесса), обратно — в базу и индекс; база помнит, под какой выбор записана.
- `app-gpui`: признак `matrix` (в dev — всегда, в release — `matrix-release`), плагин в `plugins.rs`,
  `Prefs::channels.matrix` и `.encrypted`, политики `AllowChannelMatrix` и `ChannelE2EStorePlaintext`
  (`security.rs`); «Настройки → Аккаунты → Каналы бесед» → Matrix (`account_matrix.rs`): включатель, учётки,
  вход на месте, «Проверить это устройство», «Восстановить ключи», «Шифрованные беседы». Строки — `channels.ftl`.
- Проверки: `tests/conformance.rs` — `channel::conformance` целиком на подставном сервере (`fake`, Client-Server API на
  loopback, без внешней сети), вход паролем и через браузер, комнаты и пространства, своё хранилище переживает
  переподключение, отказы проверки и ключа; `tests/e2e.rs` — второй клиент шифрует, заглушка → расшифровка с тем же
  id, своё уходит шифром; ядро — смена выбора «Шифрованные беседы».
- Размер (`docs/SIZE.md` №11): без канала 72,21 МиБ, с каналом 103,34 МиБ (+31,13); №12 —
  `opt-level = "z"` крейтам канала: +15,76 МиБ — канал в release выключен.
- Состав и дубли (`docs/SIZE.md` №13, SIZE-13): канал прибавляет 84 пакета; SQLite/IndexedDB не собираются, HTTP, TLS,
  провайдер крипто, redb, serde_json и общая криптография — те же, что у Postman. Без патча убрать нечего: 11 вторых
  версий (sha2 0.10 и rand 0.8 от `oauth2`, rand 0.10, itertools 0.15, constant_time_eq 0.4) и пары ulid/uuid,
  rmp/prost/postcard и т. п. — обязательные зависимости SDK последних версий.
