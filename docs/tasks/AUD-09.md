## Задача
- Аудит бет 0.2: реестр проверяет `limits` описания модуля (`viewers.rs`), но до хоста они не доходили —
  `Client::view_module` звала хост только с общими пределами (память 256 МиБ, общий FUEL, вход/ответ по общим
  константам): модуль работал шире, чем обещал в описании.
- Модули с импортами (просят доступ к системе, у ABI v1 их нет) реестр пропускал молча — строка только в журнале;
  в «Настройках → Просмотр вложений» отказа не видно, модуль просто исчезал из списка.

## Сделано
- Пределы по цепочке: описание (`limits`) → `Client::view_module(…, limits)` (`crates/core/src/viewer.rs` и
  интерфейс) → `Request::ViewModule` (`#[serde(default)]` — старый клиент без пределов годен) → хост
  `wasm::run(…, Limits)`: память (`StoreLimits`), топливо, вход и ответ — заявленные. `Limits::clamped` держит
  общий потолок: заявленное сверх общего и нулевое заменяется общим — песочницу можно только ужесточать.
  Тесты: заявленные меньше общих применяются (топливо, вход, ответ, память), сверх общих — потолок; и в
  песочнице (`postman-viewer`) клиент передаёт пределы в запросе.
- Отказ загрузки — в настройки: реестр разобирает раздел Import без интерпретатора (`wasm::has_imports`),
  модуль с импортами в выбор просмотра не попадает и остаётся в списке с причиной (`Registry::broken`,
  `Reason`: импорты / файл модуля / пределы / описание; описание — с именем и версией, если оно разобралось).
  «Настройки → Просмотр вложений»: строка «Не загружается: …» без выключателя (включать нечего). Тексты —
  Fluent `settings-viewers-broken*` (ru/en), формулировка импортов — «модуль просит доступ к системе». Сцена
  снимка `settings-viewers-broken` (модуль с импортом и описание без файла модуля).

## Не сделано
- Выключатель у неработающего модуля — не показан вовсе (по стилю соседних состояний: строка без кнопки),
  не неактивный.
- Пределы времени и памяти процесса (`VIEW_LIMIT`, `JOB_MEMORY`) — общие: заявленных на них в описании нет
  (схема `limits` — только `input`/`memory`/`fuel`/`output`), сторож и Job Object не менялись.
